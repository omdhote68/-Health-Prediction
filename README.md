# Health Prediction Application

Gokul Infocare - Task 2 (AI Growth & Automation Associate assessment).

A Python application for managing patient blood-test records (Create, Read, Update, Delete) with backend validation,
SQLite storage, and an AI-generated, non-diagnostic summary from the **Google Gemini API** saved in each record's **Remarks**.

> **Medical disclaimer:** this is an educational assessment prototype, **not** a medical device or diagnostic tool.
> Use fictional data only. See [Limitations](#limitations-and-medical-disclaimer).

## Main features

- Add, view, edit and delete patient records (Full Name, Date of Birth, Email, Glucose, Haemoglobin, Cholesterol, Remarks).
- Validation in backend Python (`src/validation.py`), not just in the form.
- Invalid records are **saved exactly as entered**, flagged with the reasons, and **never sent to the AI**.
- Exact duplicates are **kept and flagged** (never silently removed).
- Valid records are sent to Gemini; the reply becomes the Remarks, with a visible "Generated by Gemini API" indicator.
- If the API fails, Remarks say `AI analysis unavailable: <reason>` - nothing is fabricated - and CRUD keeps working.
- Dashboard, search/filter, delete confirmation, API connection test, retry for failed analyses.

## Technologies

Python 3.10+, Streamlit, SQLite (`sqlite3`), Google Gemini API (`google-genai` SDK), python-dotenv, pytest.

## Configure the Gemini API key

1. Create a key in [Google AI Studio](https://aistudio.google.com/apikey).
2. Create your local settings file and edit it:

```powershell
Copy-Item .env.example .env
notepad .env
```

3. Set `GEMINI_API_KEY=<your key>` in `.env`. The key is read from the environment, is never hard-coded, never shown in the UI, and `.env` is git-ignored.

The default model is `gemini-3.8-flash`. If Google retires it, set `GEMINI_MODEL` in `.env` to a currently supported model from <https://ai.google.dev/gemini-api/docs/models>.

### Protect assessment data

When a key is configured, creating or retrying a valid record sends its age and blood-test values to Google Gemini; the patient's name and email are excluded. Keep the key unset while entering the supplied assessment records unless you have confirmed they are synthetic or authorized for external processing. To demonstrate a live patient analysis, use a separate database and clearly synthetic values. The API connection test itself sends only a non-medical prompt.

## Using CRUD

| Action | Where | What happens |
|---|---|---|
| Create | **Add Patient** | Validate → (if valid) call Gemini → save. Invalid records are saved with their errors. The "Assessment test data" expander pre-fills the form with the exact supplied records. |
| Read | **Patient Records** | Table of all records (including invalid/duplicate), search by name/email, filter by validity, full remarks viewer. |
| Update | **Update Patient** | Pick a record, edit, save. Updates the same row. Changing only the email keeps the existing remarks (no new API call). |
| Delete | **Delete Patient** | Pick a record → "Delete this record" → confirm "Yes, delete it". Remaining records are listed below. |

## Validation rules

- **Full Name:** required, not only spaces.
- **Date of Birth:** a real calendar date, `dd/mm/yyyy` or `dd.mm.yyyy`, not in the future, year ≥ 1900. Validation parses the date but preserves the supplied separator and text when saving.
- **Email:** must look like `name@domain.tld` (so `hunter@gmail` and `Kris.wu.gmail.com` are rejected).
- **Glucose / Haemoglobin / Cholesterol:** required, plain decimal numbers, not negative.
- **Duplicate:** same name, date of birth, email and all three values (ignoring case/spacing). The earliest record is the original; later ones are flagged `Duplicate of #id`.

## How the AI integration works

1. `patient_service` validates the record. If invalid → stored, **not** sent.
2. For valid records `ai_service.build_prompt` creates a structured prompt containing **age and the three blood values only** (name and email are not sent).
3. The prompt asks for a short, cautious, non-diagnostic note that states units were not supplied, asks the user to provide or confirm missing units/reference ranges, avoids unsupported numeric ranges, makes no diagnosis or treatment suggestions, and recommends a qualified healthcare professional.
4. The reply is saved as Remarks with `ai_status = success`. On any failure (missing/invalid key, network, timeout, rate limit, service unavailable, empty response) Remarks become `AI analysis unavailable: <friendly reason>`.

## Limitations and medical disclaimer

- Not a medical device. AI output may be wrong or incomplete and must not guide health decisions.
- The assessment data has **no units or sex information**, so interpretation is inherently limited; the AI is told to say so. Valid DOBs retain the supplied date separator when stored.
- Gemini model names change over time; update `GEMINI_MODEL` if needed.
- No authentication or encryption - suitable for a local demo with fictional data only.
